## A. Scope

This specification defines the lightweight application-layer communication wire protocol for **Module 2 (M2)** of the iTantra offline tactical transceiver.

- **Upstream Boundary:** Consumes frozen [`SpeechMessage`](file:///c:/Users/saich/Downloads/SIH/PS26173/app/src/main/java/org/itantra/core/domain/SpeechMessage.kt) domain objects emitted by **Module 1 (M1 - Speech Subsystem)** (**[FACT]**).
- **Downstream Boundary:** Hands received, verified, and reassembled speech messages to **Module 3 (M3 - Text-to-Speech Subsystem)** for local synthesis (**[TARGET]**).
- **Transport Independence:** Completely decoupled from underlying link-layer physical transports (e.g., Wi-Fi Direct sockets, Bluetooth Low Energy L2CAP/GATT, local RF/LoRa, UDP datagrams, or Android Nearby Connections) (**[TARGET]**).

## B. Frozen M1 Input Contract

The M1 Speech Subsystem produces recognized speech utterances encapsulated in the hardened, pure-Kotlin domain model [`SpeechMessage`](file:///c:/Users/saich/Downloads/SIH/PS26173/app/src/main/java/org/itantra/core/domain/SpeechMessage.kt) (**[FACT]**):

```kotlin
package org.itantra.core.domain

data class SpeechMessage(
    val text: String,
    val language: String,
    val timestamp: Long,
    val confidence: Float? = null
)
```

### Invariant Rules at the M1 Boundary:
1. **Text Preservation:** `text` is preserved verbatim as emitted by the speech recognizer (Unicode NFC, native Devanagari Hindi or English Latin text) without mutation, lowercase folding, or punctuation stripping (**[FACT]**).
2. **Language Tag:** `language` is preserved exactly as supplied by the engine (e.g., `"en"`, `"hi"`, `"en-US"`, `"hi-IN"`) without normalization or conversion (**[FACT]**).
3. **Timestamp Semantics:** `timestamp` is a 64-bit signed epoch millisecond timestamp marking M1 boundary acquisition time. It is **NOT** a guaranteed global unique message identifier and **NOT** a distributed deduplication key (**[FACT]**).
4. **Confidence:** `confidence` is a nullable 32-bit float $[0.0, 1.0]$. When the underlying ASR decoder (such as Whisper greedy search) does not compute token confidence, `null` is preserved (**[FACT]**).
5. **No Telemetry Leakage:** Diagnostic metrics like `audioDurationMs` and `inferenceTimeMs` are strictly excluded from `SpeechMessage` (**[FACT]**).

## C. MVP Protocol Goals

1. **Compact Framing:** Minimize fixed protocol overhead to preserve bandwidth on constrained links (**[TARGET]**).
2. **Deterministic Serialization:** Bit-exact, unambiguous byte layout with consistent Big-Endian integer encoding across all platforms (**[TARGET]**).
3. **Subsystem Decoupling:** M1 (Speech), M2 (Communication), and M3 (TTS) remain strictly isolated; transport headers never pollute speech domain entities (**[TARGET]**).
4. **Corruption Detection:** Mandatory payload integrity checking via standard IEEE 802.3 CRC-32 to detect transmission bit-flips and truncation (**[TARGET]**).
5. **Transport Agnosticism:** Packet format is self-contained so that it can be carried across stream (TCP/L2CAP), datagram (UDP), or packetized radio transports (**[TARGET]**).

## E. Authoritative Wire Packet Layout

The wire-format container (`TransceiverPacket`) defines the exact binary framing transmitted across the physical link.

### Field Layout Table

| Field Name | Wire Type | Size (Bytes) | Presence | Encoding / Endianness | Owner Subsystem | Description & Semantics |
| :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| **Magic** | `UInt16` | 2 B | Mandatory | Big-Endian (`0x4954` = `'IT'`) | M2 Wire | Packet synchronizer and framing boundary. |
| **Version** | `UInt8` | 1 B | Mandatory | `0x01` (v1 MVP) | M2 Wire | Protocol version discriminator. |
| **MessageType** | `UInt8` | 1 B | Mandatory | `0x01` (`SPEECH_TEXT`) | M2 Wire | Application payload discriminator. |
| **Flags** | `UInt8` | 1 B | Mandatory | Bitmask | M2 Wire | Bit 0: `CONFIDENCE_PRESENT`; Bits 1–7: Reserved (`0`). |
| **SequenceNumber** | `UInt32` | 4 B | Mandatory | Big-Endian unsigned int | M2 Transport | Monotonically increasing per-node counter. |
| **Timestamp** | `Int64` | 8 B | Mandatory | Big-Endian signed int | M1 Boundary | Epoch milliseconds at M1 boundary acquisition. |
| **LanguageId** | `UInt8` | 1 B | Mandatory | Registry ID code | M1 / M2 | Compact language registry code (`0x00`–`0xFF`). |
| **ExtendedLangLen** | `UInt8` | 0 B or 1 B | Conditional | Unsigned integer ($1\text{--}255$) | M2 Wire | Present iff `LanguageId == 0xFE`. Length $E$ in UTF-8 bytes. |
| **ExtendedLangTag** | `ByteArray` | 0 B or $E$ B | Conditional | UTF-8 byte array | M1 / M2 | Present iff `LanguageId == 0xFE`. Verbatim tag string. |
| **TextLength** | `UInt16` | 2 B | Mandatory | Big-Endian unsigned int | M2 Wire | Exact byte length $L$ of UTF-8 payload ($0\text{--}65,535$). |
| **Confidence** | `UInt8` | 0 B or 1 B | Conditional | Quantized integer ($0\text{--}100$) | M1 Domain | Present iff Flags Bit 0 == `1`. Omitted if `null`. |
| **TextPayload** | `ByteArray` | $L$ Bytes | Mandatory | UTF-8 byte array | M1 Domain | Verbatim transcribed speech text. |
| **Checksum (CRC-32)** | `UInt32` | 4 B | Mandatory | Big-Endian (`IEEE 802.3`) | M2 Wire | CRC-32 covering Magic through TextPayload. |

## F. Exact Wire Layouts & Byte Accounting Formulas

### 1. Structure Components
- **Pre-Language Header (Always 17 Bytes):**  
  $\text{Magic}(2) + \text{Version}(1) + \text{MessageType}(1) + \text{Flags}(1) + \text{SequenceNumber}(4) + \text{Timestamp}(8) = \mathbf{17\text{ Bytes}}$
- **Language Field:**
  - **Registered Language (`LanguageId != 0xFE`):** $\mathbf{1\text{ Byte}}$ (`LanguageId`)
  - **Extended Language (`LanguageId == 0xFE`):** $\mathbf{2 + E\text{ Bytes}}$ (`0xFE` [1B] + `ExtendedLangLen` [1B] + `ExtendedLangTag` [$E$ B])
- **Post-Language Header Fields:**
  - $\text{TextLength} = \mathbf{2\text{ Bytes}}$
  - $\text{Confidence} = \mathbf{0\text{ Bytes}}$ (if null, Flags Bit 0 = 0) or $\mathbf{1\text{ Byte}}$ (if present, Flags Bit 0 = 1)
- **Text Payload:** $\mathbf{L\text{ Bytes}}$ ($L = \text{TextLength in UTF-8 bytes}$)
- **Checksum Trailer (Always 4 Bytes):** $\text{CRC-32} = \mathbf{4\text{ Bytes}}$

---

### 2. Category A: Registered-Language Packet Layout ($E = 0$)

Used for base registered languages (e.g., `"en"` &rarr; `0x01`, `"hi"` &rarr; `0x02`, `"und"` &rarr; `0x00`):

```
+----------------+---------------+----------------------------------+
|  HEADER (20B)  | PAYLOAD (Var) |           TRAILER (4B)           |
+----------------+---------------+----------------------------------+
| Magic (2B)     | Text (L B)    | CRC-32 Checksum (4B)             |
| Version (1B)   |               |                                  |
| MsgType (1B)   |               |                                  |
| Flags (1B)     |               |                                  |
| SeqNum (4B)    |               |                                  |
| Timestamp (8B) |               |                                  |
| LangId (1B)    |               |                                  |
| TextLen (2B)   |               |                                  |
| [Conf (1B)]*   |               |                                  |
+----------------+---------------+----------------------------------+
* [Conf] is 0B when confidence is null, 1B when confidence is present.
```

- **Formula (Confidence Absent):**  
  $$\text{Total Size} = 17 + 1 + 2 + 0 + L + 4 = \mathbf{24 + L\text{ Bytes}} \quad (\text{Fixed Framing Overhead} = \mathbf{24\text{ Bytes}})$$
- **Formula (Confidence Present):**  
  $$\text{Total Size} = 17 + 1 + 2 + 1 + L + 4 = \mathbf{25 + L\text{ Bytes}} \quad (\text{Fixed Framing Overhead} = \mathbf{25\text{ Bytes}})$$

---

### 3. Category B: Extended-Language Packet Layout ($E \ge 1$)

Used for regional/script variants (e.g., `"en-US"`, `"hi-IN"`) and unregistered languages (e.g., `"fr"`, `"es-ES"`):

```
+-----------------------------------+---------------+----------------------------------+
|           HEADER (22 + E B)       | PAYLOAD (Var) |           TRAILER (4B)           |
+-----------------------------------+---------------+----------------------------------+
| Magic (2B)                        | Text (L B)    | CRC-32 Checksum (4B)             |
| Version (1B)                      |               |                                  |
| MsgType (1B)                      |               |                                  |
| Flags (1B)                        |               |                                  |
| SeqNum (4B)                       |               |                                  |
| Timestamp (8B)                    |               |                                  |
| LangId (1B = 0xFE)                |               |                                  |
| ExtLangLen (1B = E)               |               |                                  |
| ExtLangTag (E B)                  |               |                                  |
| TextLen (2B)                      |               |                                  |
| [Conf (1B)]*                      |               |                                  |
+-----------------------------------+---------------+----------------------------------+
* [Conf] is 0B when confidence is null, 1B when confidence is present.
```

- **Formula (Confidence Absent):**  
  $$\text{Total Size} = 17 + (2 + E) + 2 + 0 + L + 4 = \mathbf{25 + E + L\text{ Bytes}} \quad (\text{Framing Overhead} = \mathbf{25 + E\text{ Bytes}})$$
- **Formula (Confidence Present):**  
  $$\text{Total Size} = 17 + (2 + E) + 2 + 1 + L + 4 = \mathbf{26 + E + L\text{ Bytes}} \quad (\text{Framing Overhead} = \mathbf{26 + E\text{ Bytes}})$$

## G. Regional & Script Language Semantics

### Architectural Decisions & Language Preservation Rules:
1. **Registered Language IDs:** Registered language IDs are the explicitly assigned entries in the protocol registry. Unassigned IDs are reserved/undefined and are not treated as registered languages.
2. **Exact Base Tag Matching:** Only exact canonical base language tags (`"en"`, `"hi"`, `"te"`, `"ta"`, `"mr"`, `"bn"`, `"gu"`, `"kn"`, `"ml"`, `"pa"`, `"ur"`, `"or"`, `"as"`) map to 1-byte registry IDs (`0x01`–`0x0D`).
3. **Exact Preservation of Extended Language Tags:** Regional dialects, script variants, and unlisted languages (e.g. `"en-US"`, `"en-GB"`, `"en_GB"`, `"hi-IN"`, `"hi_IN"`, `"es-ES"`, `"fr"`) are encoded as `EXTENDED_BCP47` (`0xFE`). The `ExtendedLangTag` field preserves the **exact source language string** supplied by `SpeechMessage`.
4. **Zero Normalization Policy:** The protocol mapper performs **NO** delimiter rewriting (e.g., `"en_GB"` is NOT rewritten to `"en-GB"`), **NO** case conversion, and **NO** trimming. These represent distinct source strings and are preserved verbatim on the wire.
5. **Downstream Rationale:** M3 TTS and tactical recipients depend on regional sub-tags (e.g., distinguishing British vs. American English phoneme engines, or specific Indic regional pronunciations). Stripping or mutating them at the M2 layer would cause unrecoverable metadata loss.

## H. Sequence Number Semantics

- **Format:** 32-bit unsigned integer (`UInt32`, 4 bytes, Big-Endian) covering range $[0, 4{,}294{,}967{,}295]$.
- **Counter Invariant:** Monotonically incremented by the transmitting node for every distinct `SPEECH_TEXT` packet originated by that node.

### What Sequence Numbers Support:
1. **Application-Layer Ordering:** Receiving nodes can sequence incoming messages from a given sender in chronological order.
2. **Duplicate Detection:** If a packet with an already-processed `(SenderNodeId, SequenceNumber)` tuple is received (e.g. due to multi-path radio flooding), it can be discarded.
3. **Loss / Gap Detection:** Discontinuities in sequence numbers alert the application that intermediate packets were lost over the channel.

### What Sequence Numbers DO NOT Guarantee:
- A sequence number alone does **NOT** guarantee delivery, retransmission, or network reliability (**[FACT]**).
- Retransmission logic, acknowledgment packets (ACK/NACK), and transport flow control remain the responsibility of the future transport / ARQ layer (**[ASSUMPTION]**).

## I. Checksum & Integrity Specification (CRC-32)

### Technical Specification:
- **Algorithm:** Standard IEEE 802.3 32-bit Cyclic Redundancy Check (CRC-32).
- **Generator Polynomial:** `0x04C11DB7` (standard reflected representation: `0xEDB88320`).
- **Initial Value:** `0xFFFFFFFF` (`-1L`).
- **Final XOR Value:** `0xFFFFFFFF`.
- **Byte Coverage:** Covers all bytes starting at byte offset 0 (`Magic[0]`) through the final byte of `TextPayload` (including extended language fields when present).
- **Exclusion:** The 4-byte CRC field itself at the end of the packet is excluded from the checksum computation.
- **Wire Representation:** 4 bytes (`UInt32`), serialized in Big-Endian order at the end of the packet.
- **Platform Implementation:** Standard Java/Android built-in `java.util.zip.CRC32`.

### Security vs. Corruption Boundary:
- **Corruption Detection:** CRC-32 provides robust detection of accidental transmission errors (bit flips, burst noise, packet truncation).
- **Authentication:** CRC-32 provides **ZERO** cryptographic authentication, anti-tamper security, or protection against malicious adversaries (**[FACT]**). Cryptographic signing / HMAC belongs to future security-layer specifications (**[ASSUMPTION]**).

## J. Text Length & Payload Semantics

- **Field:** `TextLength` is a 16-bit unsigned integer (`UInt16`, 2 bytes, Big-Endian).
- **Semantics:** Represents the **exact byte count of the UTF-8 encoded text string** ($L \in [0, 65535]$).
- **Critical Distinction:** `TextLength` is **NOT** the character count, code point count, or Kotlin `String.length` (**[FACT]**). Multi-byte Unicode characters (e.g. Devanagari Hindi characters which occupy 3 bytes each in UTF-8) are correctly measured by their total byte length.
- **Capacity Ceiling:** While $65,535$ bytes is the structural maximum representable by `UInt16`, this is an architectural ceiling and not a claim of practical single-frame radio capacity (**[TARGET]**).

---

## K. Confidence Encoding & Null Semantics

- **Source Type in M1:** `SpeechMessage.confidence: Float?` ($[0.0, 1.0]$ or `null`).
- **Wire Representation:**
  - **When `confidence == null`:**
    - Flags Bit 0 (`CONFIDENCE_PRESENT`) is set to `0`.
    - The 1-byte confidence field is **physically omitted** from the packet.
  - **When `confidence != null` ($c \in [0.0, 1.0]$):**
    - Flags Bit 0 (`CONFIDENCE_PRESENT`) is set to `1`.
    - Confidence is quantized to an 8-bit unsigned integer (`UInt8`, 1 byte):
      $$\text{WireConfidence} = \operatorname{clamp}\big(\operatorname{round}(c \times 100.0), 0, 100\big)$$
    - `0x00` represents a true zero confidence ($0.0$).
    - `0x64` represents full confidence ($1.0 / 100\%$).
- **Null vs. Zero Distinction:** A real zero confidence ($0.0$) has Flag Bit 0 = `1` with byte `0x00`. An uncomputed confidence (`null`) has Flag Bit 0 = `0` and occupies 0 bytes on the wire.

## L. Flags Byte Specification

The single 8-bit `Flags` byte provides explicit control and extensibility with zero padding waste:

```
+---+---+---+---+---+---+---+---+
| 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
+---+---+---+---+---+---+---+---+
  │   │   │   │   │   │   │   └─ Bit 0: CONFIDENCE_PRESENT (1 = 1B confidence follows TextLength; 0 = absent)
  │   │   │   │   │   │   └───── Bit 1: RESERVED_FRAGMENT (0 in MVP; reserved for future fragmentation header)
  └───┴───┴───┴───┴───┴───────── Bits 2–7: RESERVED (Must be 0 in v1)
```

## M. JSON vs. Binary Theoretical Design Analysis

*Note: No production JSON wire serializer exists in the codebase. The following is a theoretical design analysis.*

```
Theoretical JSON Representation (~85–120 Bytes Overhead):
{"v":1,"type":1,"flags":0,"seq":42,"ts":1726850000000,"lang":"hi","text":"..."}

Compact Binary Representation (24–25 Bytes Overhead):
[2B Magic][1B Ver][1B Type][1B Flags][4B Seq][8B Ts][1B Lang][2B Len][Payload][4B CRC]
```

### Design Analysis Comparison:
1. **Framing Overhead:** Compact binary framing requires 24–25 bytes for registered languages (or $25+E$ bytes for extended tags), whereas standard JSON formatting typically introduces ~85 to 120+ bytes of syntactic framing (keys, braces, quotes, commas) (**[DESIGN ANALYSIS]**).
2. **Parsing Overhead:** Binary deserialization uses direct byte offset reading without string parsing or object reflection (**[TARGET]**).
3. **Determinism:** Binary layout is bit-exact and endian-controlled, preventing string formatting ambiguities across platforms (**[TARGET]**).

## N. MTU & Fragmentation Analysis

### Context & Limits:
- In M1, maximum speech segment duration is capped at 30 seconds (`SpeechSegmentCollector.maxSegmentDurationSec = 30`) (**[FACT]**).
- At standard speaking rates, a 30-second utterance produces ~75 words (~450–700 UTF-8 bytes in English or Devanagari Hindi) (**[FACT]**).

### Design Intent & Target:
- **Design Target:** The protocol framing is designed to keep overhead low (24–25 bytes for base languages) so that short speech messages can fit within single-frame transmissions when the selected link transport permits it (**[TARGET]**).
- **Empirical Validation:** Actual MTU compatibility, link budgets, and whether fragmentation is required must be empirically measured after a specific transport (such as BLE L2CAP, Wi-Fi Direct, or radio sockets) is selected and integrated (**[TARGET]**).
- **MVP Baseline:** Single unfragmented frame transmission (Flags Bit 1 = `0`).
